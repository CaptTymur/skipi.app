## Общий протокол (одинаков во всех репо Skipi)

- Одна задача = один worktree = одна сессия. Задача закрыта — сессия закрывается; новая задача = свежая сессия.
- Минимальный дифф: меняй только то, что требует задача.
- Bugfix = сначала failing-test, воспроизводящий баг → фикс → зелёный прогон. Фикс без failing-test'а не принимается.
- После работы: commit + push.
- `--no-verify` запрещён.
- systemd, деплой, прод-сервер и флот ботов — вне скоупа; нужно — handoff в штаб (`skipi-ops/handoffs/`).
- Инцидент (регрессия, потеря данных) → SKI-INC-NNN в `skipi-ops/incidents/`.
- Сессия запускается из папки этого репо (`cd <репо> && claude`), не из корня. Если этого файла нет в списке `/memory` — сессия поднята неправильно: остановись и сообщи человеку.
- Обмен с другими агентами — через артефакты на диске (коммиты, handoffs, verify-отчёты), не копипастом между окнами.

## Командное заверение безопасной параллельности (опыт Crewing Pilot + Seafarer)

Обязателен общий контракт «Безопасная параллельность Skipi» из абсолютного `/home/linux/Developer/AGENTS.md` и роль единственного действующего координатора `/home/linux/Developer/skipi-parallel-coordinator/AGENTS.md`. Каждый писатель Seafarer сохраняет own immutable заявку и напрямую вызывает этого координатора (когда его сессия открыта из его дома; иначе — заявка одной строкой менеджеру) в составе команды; менеджер наблюдает, relay — только fallback. События: `START / PREP`, `BEFORE_STAGE` для `IMPLEMENT / VERIFY / BUILD / OWNER_REVIEW / INTEGRATE / FINALIZE / END`, затем `AFTER_STAGE`; `CHANGE` — до расширения работ, heartbeat — не реже раза в 5 минут при активной записи. До свежего stage-specific certificate (epoch/lease/revision/input-content identity) и `PERMIT_CURRENT` перед ограниченным действием — `WAIT`; старый epoch или replay не дают новых прав.

Отсутствующий координатор, STOP/expiry или устаревший/неполный вход затрагивают текущую ограниченную стадию: новые записи прекращаются на безопасной границе, резерв остаётся `DRAIN_REQUIRED` до `ACK_STOP` и первичного terminal evidence завершения всех пишущих операций. Конфликтующий поток остаётся `B_WAIT` до подтверждённого освобождения. Долгие `BUILD / VERIFY` требуют доказанного активного runtime heartbeat/renew до запуска. Инструменты и hooks в продукт не устанавливаются по этому контракту.

Каноническая правка этого файла не обновляет инструкции старых linked worktree автоматически: каждый писатель явно перечитывает абсолютные общий `AGENTS.md` и `AGENTS.md` координатора вместе со своими локальными инструкциями. Менеджер финализирует и собирает последовательно. Действующие owner acceptance, parked/STOP, guard/review и границы записи сохраняются; установка этого контракта не возобновляет припаркованную задачу и не является продуктовой приёмкой.

Причина: слово владельца 07.10 (DECISIONS skipi-ops (1014)) — координатор и инспектор контекста в команде каждой задачи; новые правила в ПЕРЕДАЧЕ — с причиной и сроком снятия. Критерий снятия: контракт целиком живёт в общем Developer/AGENTS.md и каноне координатора, и две карточки подряд прошли без ссылки на эту секцию — тогда секция заменяется одной строкой-указателем.

## Контекст-дисциплина сессии (одинакова во всех репо Skipi; аддитивно к канону MDL, skipi-ops DECISIONS 2026-08-07)

- **WORKLOG — состояние задачи живёт на диске, не в окне.** Путь к task card даёт постановка задачи. После каждого значимого шага дописывай в секцию WORKLOG card: принятые решения, обнаруженные грабли, текущий шаг. После компакта/обрыва контекста — сначала перечитай card, потом продолжай. При закрытии сессии заполни подсекцию ПЕРЕДАЧА: что сделано / что осталось / что не работает и почему. Новая сессия по той же задаче стартует с card, а не с нуля.
- **Баг → регрессионный тест в том же fix-коммите.** Каждый пойманный баг (инцидент, red review, owner-находка) получает тест, который его ловит, в самом fix-коммите — не «потом». Это уточняет строку bugfix общего протокола: failing-test не только пишется первым, но и остаётся в fix-коммите как регрессионный.
- **Правила из ошибок.** Повторённая ошибка или указание на неё → не объяснение в чате (испарится), а короткий инвариант в секцию «Правила из ошибок» этого файла, с критерием удаления.
- **Контекст-экономия.** Широкое чтение/поиск кода — через Explore-субагента: в окно возвращается вывод, не файлы. Граница контекста задачи = этот репозиторий + контракты (skipi-contracts); весь флот в окно не тянуть.

### Дисциплина негативных дриллов

Пять правил ниже куплены волной №321 (14.09): слайс 1 «Пакетов» (06.09) записал
в сьют дословный запрет кнопки Share со словами «sharing a package off the phone
is **slice 2**», и слайс 2 встретил его красным на первом же прогоне — ровно в тот
момент, когда проще всего «подкрутить тест». Различать надо два вида дриллов:
**дрилл-инвариант** защищает пользователя и срока не имеет (нет `_identity` в
архиве, нет `navigator.share`, отмена ≠ «Отправлено», нетронутый sha-пин) — его
правка эрозия ВСЕГДА; **дрилл-граница слайса** фиксирует датированное решение об
объёме и написан ради того дня, когда следующий слайс придёт.

- Каждый негативный дрилл при рождении несёт **условие своей отмены** (какой слайс
  или чьё слово его снимает); без условия его снимает только владелец (источник: №321, 14.09; удалить когда: два подряд слайса, где ни один дрилл не снят без условия).
- Утверждение снимается **только вместе с заменяющим**: счёт утверждений на
  поверхности не уменьшается и пишется в карточку числом «до/после» (источник: №321, 14.09; удалить когда: два подряд слайса с непадающим счётом).
- sha-пины **никогда не перебазируются в той карточке, которая их ломает** —
  перебазирование живёт отдельной карточкой, называющей сдвиг (источник: №321, 14.09; удалить когда: не удаляется, пока в сьюте есть sha-пины).
- Правка дрилла ПОСЛЕ красного, не названная в задании заранее, — доклад
  менеджеру; «чтобы стало зелено» — стоп-слово (источник: №321, 14.09; удалить когда: два подряд слайса без внеплановых правок сьюта).
- Измеримый критерий эрозии — счёт утверждений во времени: падает — значит
  эрозия (источник: №321, 14.09; удалить когда: счёт перестанет быть измеримым, т.е. сьют уйдёт из репозитория).
